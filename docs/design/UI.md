# UI・操作契約

YA-D03 / 2026-10-02。旧補足section-3を現行v0.2へ統合する。既存要件の表示・操作契約であり、画面実装・完成アート・実機受入を表さない。[REQUIREMENTS](REQUIREMENTS.md)、[ITEMS_ECONOMY](ITEMS_ECONOMY.md)、[COMBAT_CORE_V1](COMBAT_CORE_V1.md)、[PVP_TOURNAMENT](PVP_TOURNAMENT.md)を優先する。

## 1. 状態と遷移

タイトル/接続 → 拠点 → 育成/装備/工房 → ダンジョン/作戦確認 → 出撃/観戦 → 結果/受取 → 拠点。交換・取引所・交流は拠点から入る。定期大会の受付/登録/観戦/結果は現行大会設計の別フローで、旧15画面だけで全v0.2を網羅したとしない。

出撃中の職/装備/ビルド編集は現在戦闘への変更と次回下書きを明確に分ける。画面を閉じることと作戦停止は別操作。接続が失われた表示は最後の同期時刻と再接続中を示し、古いHP/MPを現在値として見せない。8時間進行と公式結果の実行先はD01に依存し、UIから常時稼働を保証しない。

## 3. 不可逆操作と再取得

合成の確認には、正負両方の能力差分、費用、消費品、「合成後は他プレイヤーへ渡せない」「上書き前のアクセサリーは戻らない」を表示する。装備解除だけでは未合成ドロップ品を本人専用にしない。BOUND初期支給品は例外として表示する。

交換はチャット上の約束ではなく、確定先に保存された提示内容とVersionだけを確認対象にする。提示変更・見積期限・Version競合では旧確認を流用しない。確定後の応答断では既存操作の結果を再取得し、成功/失敗を推測しない。[API](API.md)のoperation/receipt契約に従う。

## 4. 表示とアクセシビリティ

FR18/NFR08/NFR10に従い、数値/名称の拡大、色だけに依存しないレア名称/形状、フォーカスの可視化、点滅軽減、BGM/SE個別設定を設計へ含める。キーボード/パッド、長い日本語、設定保存失敗、狭幅の情報順を実クライアントで確認する。

旧640×360描画/1280×720 UI、文字100–200%、48pxキャラ/32pxタイル、上左中右下の配置、4職1地域のアセット制作順は制作初期案として保持する。承認済み解像度・達成済み可読性・完成アセット数とはしない。実サイズはYA-01の軽量性/読みやすさ計測で評価する。素材ライセンス台帳は実素材の導入時に作成し、未取得ライセンスを承認済みにしない。

## 5. 未実行の画面受入

1. 文字拡大/長い名称/色補助/フォーカス/パッドで情報・操作が欠けない。
2. 出撃中編集が次回用であること、切断中の最後の同期時刻が判別できる。
3. 全滅の終了時刻は公式イベント+300秒。再ログインで制限を延長しない。大会敗北を同じPvE表示へ無条件流用しない。
4. 合成確認に不可逆性と悪化差分、交換変更に同意解除、市場応答断に結果再取得が見える。
5. Combat v1では通常攻撃/MP回復/KOのみを実データとして表示し、未実装技能の理由や敗因を捏造しない。

これは試験計画でありPASS記録ではない。実画面・入力・描画・アクセシビリティ受入はYA-01/04/19と対応機能Taskに残る。
