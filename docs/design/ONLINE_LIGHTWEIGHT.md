# オンライン方式・軽量化・販売条件

Revision 0.2 / 2026-09-13。ユーザー指定はSteam販売・軽さ・600円買い切り・参考作品。具体的なサービス構成は比較案であり、D01の費用判断を代行しない。

## 1. 参考作品から確認できた範囲

『めっちゃカメレオン』の開発者インタビューはサーバー費ゼロと紹介している。[N01] ただし今回取得できた一次資料だけでは、全ゲーム進行・保存・不正対策の内部構成までは確認できない。同作がSteamで売られていることから、Steamが全ゲーム処理をホストしていると推定しない。

SteamのロビーはSteam側で管理され、参加者探し・部屋への参加・招待に使える。ゲーム開始後は別のゲームサーバーまたはホスト役ユーザーへ接続するモデルである。[N02] Steam Networkingの新しいAPIは既定でValveネットワーク経由の中継を使える。[N03] いずれも任意のMMO計算や運営DBを提供する契約とは区別する。

Steam Inventoryにはサーバーレスな持ち物管理もあるが、クライアントを信用しない方式の付与は設定したプレイ時間ドロップ等に制約される。任意のゲーム達成に応じた明示的な品の付与には、状態を把握する信頼済みサーバーを使う設計が公式に説明されている。[N04]

## 2. 比較と当面の設計

|担当|A: プレイヤーホスト中心|B: 最小の公式判定基盤を併用（提案）|
|---|---|---|
|配布・所有確認・招待|Steam|Steam|
|部屋探し|Steam Lobbies|Steam Lobbies。参加資格の最終確認はゲーム側|
|街の移動・見た目|ホスト型P2P|P2Pを検証候補とする。経済に影響しない見た目だけ|
|自動戦闘|参加者端末|公式Combatワーカー。画面描画はクライアントだけ|
|全員終了後|実行端末はなくなる。復帰時に計算するなら端末結果の信頼性が別課題|8時間以内の指示を公式基盤が進行・確定|
|交換・合成|保存しても元の獲得過程の正しさは別問題|単一の所有権台帳で原子的に処理|
|公式PvP大会|ホストの申告だけを公式結果にしないため別の検証設計が必要|参加スナップショットから公式側で計算し、同じ結果へ収束|
|費用|常時専用ゲームホストを持たない。外部サービスの条件と限度は確認が必要|計算・保存・バックアップ費が残る。ゼロ円や収容人数を保証しない|

Bでも画面付きGodotプロセスを1パーティーにつき常駐させない。純粋C#のイベント計算を複数冒険で共用する。描画フレームと論理時刻を切り離し、不要な常時通信を減らす。

P2Pで公式戦闘を重複計算し、その結果を公式基盤が丸ごと再計算する方式を、根拠なくCPU削減策と説明しない。削減を狙うのは描画、高頻度の位置通知、不要な常駐プロセス、ログ量。公式判定に必要な計算自体は残る。

## 3. 通信契約

ILobbyService、ISocialTransport、IAuthoritativeGameServiceを分離する。最初の試作は従来のHTTPS/WSSを利用できる。Steam Lobbies/P2P Adapterの実検証はYA-12Bで行う。SDRを汎用HTTPSへ自動適用する前提にしない。

P2P候補は街の座標・向き・エモートなど、資産と勝敗に無関係な表示情報に限る。全員相互接続ではなくホスト型を比較し、40人時の送受信量とホストCPUを測定する。部屋主は位置表示の調停者であり、アイテム付与やBAN権限を持たない。

ロビーmetadataにはroom_id、protocol_version、world_id、表示タグだけを置く。認証秘密、所持品全体、報酬seedを置かない。ホスト変更時はroom_epochを増やし古い表示パケットを破棄、最大10秒の復旧目標で再同期する。これは実装目標で、Steamの自動ホスト移行機能を保証する記述ではない。

ホスト消失・P2P経路停止は街の再接続として処理し、公式の出撃・報酬・大会勝敗を変えない。40人のP2Pが測定に不合格なら低頻度WSSを比較し、D02の40人や共通経済を無断で削らない。通報対象のチャットとギルド権限は公式基盤で扱う。

## 4. クライアントの軽量化

第一候補はGodot 4系の2D、Compatibilityレンダラー。公式資料はCompatibilityを低性能・古いハードウェアや高度な描画を要しない2D向けの候補としている。[N05] 他エンジンより常に最軽量とは断定しない。

C#/.NETは既存の設計案を維持し、Combatを画面から切り離す。配布サイズやメモリが目標に届かない場合は、アセット・描画・ログを先に計測し、必要ならGDScript等を比較する。C#をユーザーの指定言語として扱わない。Windows優先、具体VersionとSteamバインディングはYA-01/12で固定する。

|項目|初期の測定目標（未達成）|
|---|---|
|画面|1080p、40人の街・12人レイドで60fps。30fps上限設定も提供|
|非アクティブ|描画5fps上限、最小化時は描画停止。ネットワーク時刻や作戦期限は遅くしない|
|メモリ|4職1地域のRelease版でプロセスworking set 512MiB以内、50職版で1GiB以内を候補目標|
|配布|初期配布500MiB以内を候補。Steamクライアント本体は計測対象外|
|演出|2D sprite atlas、画面外描画抑制、粒子数上限、派手なシェーダーは既定で無効|
|ログ|直近イベントのリングバッファ。8時間分を全量RAMへ溜めない|

基準PC、OS、内蔵GPU、ドライバー、解像度、測定時間をYA-01で固定し、起動後30秒の安定化→10分の同一シーンで計測する。Steam公開の最低スペックは計測してから記載する。開発PCの高性能GPUで動いただけで軽量性を合格にしない。

## 5. 600円買い切り

日本円の通常価格を600円とする。価格を自動で上げない、月額課金を補わない。初期案の性能課金なしを維持する。Steamへの価格登録そのものは公開準備で行い、今回登録済みとは扱わない。

販売価格は運営者の純受取額ではないため、600円×本数をそのまま運営費の原資や利益として確定しない。地域別設定、割引、精算条件、予算は公開前に確認する。本書では料率や為替の未検証値を使った収支予測を置かない。

## 6. 検証と判断順

YA-01: 軽量クライアントと決定的Combatの測定。YA-12B: Steam部屋検索・招待・ホスト退出・40人表示の技術検証。YA-P02: 公式大会の署名済み/サーバー由来スナップショットによる再現結果。YA-21: 放置数と保存量を含む負荷/費用測定。

完全P2Pへ変更する場合は、共通市場・検証済み報酬・公式大会・全員終了後の進行のどれをどう代替するかを決定してから公式ワールドを実装する。承認済み機能を残したまま月額ゼロが保証されるとは説明しない。
