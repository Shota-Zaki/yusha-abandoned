# 要件定義

Version: 0.1 / 2026-09-13

`U`はユーザー指定、`P`は不足を補う仮決定。Pは変更可能だが、後工程が推測で上書きしないよう初期仕様として定義する。

## 1. 機能要件と受入条件

|ID|出所|要件|受入条件|
|---|---|---|---|
|FR01|U|タイトルは勇者アバンド。放置育成＋MMO|タイトル・街・協力・育成ループが接続される|
|FR02|U|Steamサービスを利用|Steam認証と所有確認を実機で通す。ゲーム処理の配置はD01で確定|
|FR03|U|約50職。戦士・白魔法使い・黒魔法使い・僧侶を含む|JOBSに50件の一意ID、武器制限、役割、固定スキルを持つ|
|FR04|U|特定職の最大Lv組み合わせで上級職解放|同一キャラクターが全前提を達成した時だけ解放。前提職Lvは消費しない|
|FR05|U|初級職も差別化し、上級職一択にしない|全職で同じ成長予算。初級20職の終盤ベンチマークをQA14で確認|

|FR07|U|武器の装備可否は職業で決まる|出撃・転職・装備変更のサーバー検証で禁止武器を拒否|

|FR29|P|データ駆動コンテンツ|職業、スキル、敵、抽選表をVersion固定した定義として検証|
|FR30|P|段階的な出荷|4職の縦切り、50職の完成、協力・運用試験のGateを分ける|

## 2. ゲーム上の対象外（v1）

対人PvP、プレイヤーによる強奪、現金賭博、Steamコミュニティ市場への装備出品、無制限の放置蓄積、クライアントだけで確定する交換可能報酬、シームレスな全世界同一マップ、ユーザー運営サーバーと公式経済の接続はv1の対象外。必要になった場合は別設計とする。

|NFR02|通常API p95 300ms以内、取引p95 500ms以内（外部Steam待ちを別計測）|1,000CCU相当の段階負荷試験。容量保証は計測後|

## 4. データ・外部サービス

SteamIDはJSONでは文字列。認証後のSteamIDだけをアカウントキーとして採用する。セーブ・キャラクター・所持品・取引の正本はDB。Steam Cloudを利用する場合もUI設定だけとする。

Steam AppID、配布資格、運営サーバー契約、決済方式は外部条件である。これらが未確定でも純粋な戦闘ロジック、カタログ、UI、DB契約の設計・実装は進められる。
